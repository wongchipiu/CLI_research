# Quant Research Console 系统设计

## 1. 产品定位

这是一个本地优先的量化研究操作台。它不重新实现研究和风控逻辑，而是把两个 Python 项目的稳定 CLI 与版本化 JSON 契约包装成可视化流程：

```text
浏览器操作台
    ↓ 结构化表单、确认、状态展示
本地安全桥接服务
    ↓ 固定命令允许列表、参数校验、审计
CLI_research ── versioned JSON ── gpt_quant
    ↓                              ↓
数据/回测/Radar/研究证据          验证闸门/模拟账本/Agent
```

网页不应该拼接任意 shell 字符串，也不应该直接读原始行情。所有动作由固定 `command_id` 和结构化参数描述，本地桥接服务将它们转换为参数数组后执行。

## 2. 用户模式

### 普通模式

- 使用业务语言解释每个动作。
- 用向导约束正确顺序。
- 隐藏路径、环境变量和大部分高级参数。
- 把 JSON 转成指标卡、检查清单、表格和明确结论。
- 不显示“Sharpe 高”等同于“策略有效”的误导性文案。

### 专家模式

- 显示对应的完整 CLI 命令。
- 提供参数、输出文件、退出码和口径说明。
- 支持复制命令到终端复现。
- 显示原始 JSON、哈希、schema 版本和执行模型。

## 3. 页面与能力映射

| 页面 | CLI_research | gpt_quant | 主要输出 |
|---|---|---|---|
| 数据中心 | `update_data.py`、`check_data.py` | — | 质量摘要 |
| 策略研究 | `run_backtest.py`、`run_parameter_scan.py`、`quant workflow` | 验证适配器 | ranking、scan、metrics、decision |
| 每日雷达 | `quant scan`、`quant signals track` | — | 雷达快照、信号跟踪 |
| 结果中心 | 月度汇总、metrics 读取 | `validate-cli-result` | 支持、反证、缺口 |
| 模拟账户 | `generate_paper_signal.py` | `paper-*` | 信号、账本、交易和审计 |
| 风险控制 | `run_live_risk.py`、状态机模拟 | 风险规则 | NORMAL/FREEZE/REDUCE/LIQUIDATE |
| 专项分析 | 事件分析、品牌评分、资产复盘 | Agent demo | 独立研究结果 |
| 操作手册 | 全部命令 | 全部命令 | 可复制复现说明 |

## 4. 安全分级

| 级别 | 示例 | 页面规则 |
|---|---|---|
| 只读 | 数据质量、验证结果、模拟报告、preflight | 可以直接运行；显示输入和输出 |
| 写入结果 | 雷达、探索回测、信号跟踪、专项分析 | 运行前显示输出目录；记录审计 |
| 关键确认 | 正式参数扫描、统一 workflow、模拟订单、调仓、风险快照 | 二次确认；显示不可逆影响；禁止重复点击 |
| 高风险维护 | 全量格式迁移 | 普通页面禁用；备份后由维护者手工运行 |

`normalize_data.py` 当前没有 dry-run 或 `--help`，并会重写全部日线 Parquet，因此不能作为普通页面按钮暴露。

## 5. 本地桥接服务要求

后续桥接服务建议使用 Python HTTP API，并满足以下约束：

1. 仅监听 `127.0.0.1`，默认不暴露到局域网。
2. 只允许固定命令 ID，不接受自由输入的 shell 命令。
3. 使用 `subprocess` 参数数组并设置固定工作目录，禁止 `shell=True`。
4. 路径参数必须解析并限制在 `CLI_research`、`gpt_quant` 和用户明确配置的输出目录内。
5. 写入、最终测试、模拟成交和风险动作必须带一次性确认令牌。
6. 每次运行记录命令 ID、规范化参数、开始/结束时间、退出码、输出路径和产物哈希。
7. 长任务使用任务 ID 和增量日志；刷新页面不能重复提交任务。
8. 页面只读取摘要 JSON；原始行情、大日志和交易明细不自动加载进浏览器。

## 6. 推荐实施顺序

1. 只读桥接：健康状态、质量摘要、结果列表、metrics 可视化、验证器、paper-report、risk-preflight。
2. 低风险写入：雷达扫描、信号跟踪、探索回测、专项分析。
3. 正式研究：边界预览、冻结实验、最终测试确认、统一 workflow。
4. 模拟账本：初始化、估值、信号、订单、调仓、撤销和审计。
5. 风险控制：先 paper 环境，再开放一次性快照；实盘连接保持独立硬锁。

## 7. 部署边界

能够执行本机 CLI 的版本应运行在本机。公开托管页面无法安全、可靠地访问用户电脑上的 Python 环境和研究文件。如果未来需要远程访问，应部署受认证的专用后端执行节点，而不是让浏览器直接连接本机 shell。
