# 案例：怎样从一次模拟信号测试得出可靠结论

这个案例不研究“买哪只股票”，而是回答一个更基础的问题：**同一个收盘信号，在程序重启前后会不会被重复执行？**

## 1. 先写问题和失败条件

研究问题：账本收到一个 `next_open_v1` 目标仓位后，是否只执行一次，并在重启后继续记得它？

事前失败条件：

- 首次信号没有形成预期订单；
- 重启后 `processed_signal_ids` 丢失；
- 同一 `signal_id` 再次改变持仓或新增订单；
- 使用 30 分钟前的价格仍能执行。

把失败条件写在运行前非常重要。否则看到任何“成功输出”后，都容易临时把标准改成对结果有利的说法。

## 2. 运行完全离线案例

```bash
cd /Users/brucehuang/Documents/gpt_quant
../CLI_research/.venv/bin/python -B scripts/demo_paper_workflow.py
```

脚本使用临时目录、合成证据和本地模拟账户，不需要 API Key，不读取真实行情，不留下账户状态，也不会连接券商。

关键观察值：

| 观察 | 预期 | 含义 |
|---|---:|---|
| `first_order_count` | 1 | 首次目标形成一个模拟订单 |
| `filled_orders_after_restart` | 1 | 状态重启后订单仍在 |
| `processed_signals_after_restart` | 1 | 信号唯一键已经持久化 |
| `replay_result` | 已处理 | 重放没有产生第二次成交 |
| `stale_price_result` | 价格陈旧 | 执行价格时效检查生效 |

## 3. 分开“观察”“推断”和“结论”

观察是程序直接输出的事实：一个订单、一个已处理信号、重放被拒绝、陈旧价格被拒绝。

推断是由多项观察支持的解释：在该确定性案例覆盖的路径中，信号幂等键和价格时效状态能跨重启保持。

结论必须限定范围：**该案例支持 S3 的账本可信性约束，但不提供任何策略收益证据。**

不能得出的结论：

- AAPL 或动量策略值得买；
- 真实行情数据质量已经通过；
- 模拟账户已经运行 63 个交易日；
- 节假日日历、停牌或真实开盘撮合已经完整模拟；
- 可以连接或授权实盘账户。

## 4. 下一步问题如何自然产生

一个好结论会指出下一项仍未知的事情，而不是无限扩大已知范围。这个案例后的合理问题是：

> 使用真实且通过验证的研究证据，连续记录至少 63 个不同模拟交易日后，证据是否保持有效，执行偏差、拒单、回撤和持仓状态是否仍在预设范围内？

这比“测试通过，所以可以买”多了一层关键纪律：每一步只回答它实际检验过的问题。
