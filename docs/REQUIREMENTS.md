# 量化交易 Agent — 需求文档 v1.1

> 定稿日期：2026-06-11。本文档是所有开发 session 的唯一需求来源，开工前先读本文件，不要重新讨论需求。

## 1. 项目定位

个人量化研究系统，运行形态为 **Claude Code 项目**：

- **确定性层（不耗 token）**：纯 Python 实现的数据管道、回测引擎、报告生成。可以脱离 LLM 独立运行。
- **Agent 层（耗 token，低频）**：Claude Code skills + 约定，LLM 仅作为"研究助手"——由用户主动发起策略研究、因子设计、回测结果解读、复盘。**LLM 不参与任何实时/自动化交易决策。**

第一期范围：**研究 + 回测**。不含模拟盘、不含实盘、不含自动定时任务。

## 2. 目标市场

| 市场 | 数据源（免费） | 关键约束 |
|------|---------------|----------|
| A股 | akshare（主）/ tushare（备） | T+1、涨跌停板、印花税+佣金、停牌 |
| 美股 | yfinance | 时区（美东）、T+0、拆股/分红复权 |

数据粒度第一期只做**日线**（日线足够支撑中低频策略研究，且数据量小、免费源稳定）。分钟线列为二期可选。

## 3. 功能需求

### 3.1 数据层（纯 Python）
- R1. 拉取并增量更新 A股/美股日线 OHLCV，本地存储为 Parquet（按市场/标的分区）。
- R2. 股票池管理：A股指数成分（如沪深300）、美股自选清单，存为 YAML 配置。
- R3. 数据质量检查脚本：缺口、停牌、异常值、复权一致性，输出文本摘要（供 agent 读摘要而非读原始数据）。

### 3.2 回测层（纯 Python）
- R4. 向量化回测引擎（基于 pandas/numpy，或选型 vectorbt），支持：手续费、滑点、A股 T+1 与涨跌停约束、美股 T+0。
- R5. 标准绩效指标：年化收益、最大回撤、夏普、卡玛、胜率、换手率，与基准（沪深300 / SPY）对比。
- R6. 回测结果落盘：`results/<策略>_<日期>/`，含 metrics.json（< 2KB 摘要，给 agent 读）+ 净值曲线图 PNG + 交易明细 CSV。

### 3.3 策略库（纯 Python）
- R7. 统一策略接口：输入行情 DataFrame → 输出目标仓位/信号 DataFrame。
- R8. 内置基线策略：双均线、动量轮动、均值回归（布林带），作为接口示范和业绩基准。

### 3.4 Agent 层（Claude Code）
- R9. CLAUDE.md：项目约定 + 明确禁令（不读 data/ 下原始数据文件，只读 *_summary.txt / metrics.json）。
- R10. Skills：
  - `/research <想法>`：调研策略思路，输出结构化研究笔记到 docs/research/。
  - `/backtest <策略> [参数]`：运行回测脚本，读取 metrics.json 给出解读。
  - `/review`：对比 results/ 下多次回测，给出改进建议。
- R11. 所有 agent 产出（研究笔记、结论）写入 docs/，形成可追溯的知识库。

## 4. 非功能需求

- N1. **Token 经济性是一级约束**：任何重数据操作必须有"脚本算、agent 读摘要"的形态；详见 PLAN.md 第 4 节。
- N2. Windows 11 本地运行，Python 3.11+，用 uv 管理依赖。
- N3. 全部免费数据源，第一期零现金成本。
- N4. 确定性层有最小单元测试（回测引擎的费用/T+1 逻辑必须有测试）。

## 5. 明确不做（第一期）

- 不接实盘/模拟盘券商接口；不做盘中实时信号；不做定时自动运行的 agent；
- 不基于 claude-code-sourcemap 泄露源码做任何开发（无许可证，法律风险）；
- 不做分钟级及以下高频数据；不做机器学习选股（二期再议）。

## 6. 二期扩展：IBKR 账户级风控熔断器

> 变更日期：2026-07-22。该扩展不改变第一期研究/回测边界；它是一个独立、确定性的运行时服务，LLM 不参与触发判断。

- R12. 通过官方 IBKR TWS API / IB Gateway 读取账户基础货币净值、账户 Daily P&L、持仓和活动订单；第一阶段只允许连接 Paper 账户。
- R13. 支持三级、单日单向升级的风险动作：日亏损达到 3% 时冻结新增委托并撤单，达到 4% 时将股票仓位降至触发前的 50%，达到 5% 时取消全部委托并清空所有股票多头/空头。
- R14. 熔断状态、当日起始净值和目标仓位必须原子化持久化；进程重启后不得重复减仓，也不得在同一交易日自动解锁。
- R15. 对数据陈旧、连接中断、部分成交、拒单和停牌采用 fail-closed 行为：停止新增风险、持续告警和复核剩余仓位，但不得根据陈旧 P&L 猜测并触发清仓。
- R16. 默认 dry-run；Paper 下单也必须配置精确账户号。实盘路径必须同时通过配置开关、精确账户匹配和环境变量三重确认，且不在本阶段启用。
- R17. 提供完全不连接券商的仿真适配器与单元测试，覆盖阈值、重复执行、部分成交、重启恢复和实盘保护。

## 7. 三期扩展：下一代大模型研究系统的准入加固

> 变更日期：2026-09-01。该扩展先修复研究证据到本地模拟账本之间的信任边界；不接模型、不连接券商，也不产生实盘授权。

- R18. `validate-cli-result` 不得接受命令行自报的模拟天数或人工复核；模拟天数和账户健康只能来自持久化账本。当前阶段最高状态保持 `PAPER_TRADING`，实盘批准必须由后续独立、签名且可撤销的批准包实现。
- R19. 模拟目标信号升级为 `paper_target_signal` v3；`signal_id` 必须由所有会影响执行的字段按 canonical JSON 重算，消费方必须拒绝 ID 与载荷不一致的信号。
- R20. 信号必须绑定研究证据哈希、策略包哈希、策略、市场、股票池和信号数据哈希；模拟账户和当前证据文件均须重新核对这些绑定。
- R21. 金额、价格、权重和持久化账户数值必须是有限数；`NaN`、正负无穷和非法布尔/字符串数值必须 fail closed。
- R22. 调仓前必须一次性验证所有目标标的及现有持仓的执行价格完整、新鲜且为正；缺价时不得估值、下单、写入 `processed_signal_ids` 或留下部分状态变更。
- R23. 正式交易所日历作为后续独立条目实现；在完成前，离线账本的工作日判断不得被描述为完整 NYSE/SSE/SZSE 日历。
- R24. 交易日历 provider 必须精确锁定版本并在运行时校验；安装版本、日历名称或覆盖范围不匹配时 fail closed，不得回退到工作日判断。
- R25. 美股使用 XNYS；中国 A 股使用 XSHG 交易日规则，并以显式 `XSHG+XSHE` 契约身份表示 SSE/SZSE 共用的内地休市安排。节假日、提前收市和午休必须由日历 schedule 判断。
- R26. 模拟信号升级为 `paper_target_signal` v4，把 `calendar_id` 纳入内容身份；模拟账户持久化同一身份，生成、消费、估值三处均须核对。
- R27. 日历覆盖范围外的日期必须拒绝并要求升级冻结版本；不得用推算、未来行情或人工补工作日绕过。
