# CLI_research × gpt_quant 整合开发计划

日期：2026-08-28。首次条目：M7-S0（代码盘点与整合设计）；后续 M7-S1 实施结果见 [M7_S1.md](M7_S1.md)。

本文基于本机源码和离线验证，不是根据项目名称推测的目录方案。S0/S1/S2 已完成，S3–S9 尚未实施。已完成轮次均未迁移仓库、安装依赖、更新行情、连接券商或创建定时任务。

## 1. 结论

以 `CLI_research` 为主项目，保留其数据、组合回测、策略和研究模块；复用 `gpt_quant` 的验证闸门、Agent 协议、审计和本地模拟账户。先统一使用入口和数据契约，再决定是否物理合仓。

实际分工与此前聊天中的假设不同：`CLI_research` 已经是主要量化计算底座，并非仅有研究报告；`gpt_quant` 的优势是研究流程编排与验证，不是成熟的实盘执行系统。

首个新增产品目标：**美股收盘后异动发现 → 留存候选及当时证据 → 跟踪未来 1/3/5/10/20 个交易日表现 → 研究验证**。扫描候选不直接生成订单，也不宣称预测能力。

仅枚举 `results/*/metrics.json`，并读取允许的摘要；没有将 `data/` 原始行情、交易明细 CSV 或图表读入上下文。

抽样的美股摘要是 `scan_momentum_us_20260721-213447-556684/metrics.json`；A股摘要是 `scan_momentum_cn_20260721-213447-754216/metrics.json`，后者另有样本外表现、稳定性、滚动验证和邻参检查未通过。部分事件研究/公司评分也使用 `metrics.json` 文件名，统一入口必须先识别产物类型，不能将所有同名 JSON 当作策略验证证据。

### 已复现、应先修复的问题

1. **冻结仓位后资金约束失效。** CLI 的 `backtest/engine.py:49`：两只股票，第一天满仓 A；第二天 A 为 NaN、目标切换为满仓 B，实际权重输出 A=1、B=1，总仓位 2.0。输入权重检查通过，但约束处理后未重新限制可用资金。合成案例已在内存复现。
2. **模拟交易天数可重复累计。** GPT 的 `paper.py:129`：依次估值 2026-01-05、01-06、01-05，只有两个不同日期却累计 3 天。需要拒绝日期倒退，并对有效交易日去重；现有 `calendars.py` 只有日内时段定义，不能代替完整交易日历。合成案例已在内存复现。

### 代码审阅发现，尚需专项测试

- **缺行情与可交易性混淆：** CLI 的 `data/research.py:39` 在进入引擎前对价格整体前填，可能抹掉引擎依赖 NaN 识别的不可交易状态。应分离估值价格和可交易掩码。
- **成交时点不同：** CLI 是当日收盘信号/当日收盘成交，GPT 是次根开盘成交。收盘后才知道的扫描条件不得假设在同一收盘价成交；现有收益不直接横向比较。新增路径先明确 `signal_as_of`、`available_at`、`execution_at`，采用下一交易时段成交规则。
- **样本外被用于选参：** `run_parameter_scan.py:57` 按 OOS 表现排序；`evaluation.py:122` 将传入的固定决策矩阵切为多个测试段，没有每折只用训练段选参的流程。因此现有“最佳 OOS”不能当作完全未参与选择的最终测试集。
- **证据契约不完整：** 结果 JSON 缺统一版本/产物类型；验证器对部分通过标记使用 `bool(...)`，应拒绝字符串等非布尔类型，并检查有限数值、完整字段和数据/代码版本。持仓退出次数与逐笔已完成交易的指标语义也需区分。
- **模拟估值时间和信号时间混用：** `gpt_quant/cli.py:168` 的调仓使用 `generated_at`，价格来自信号文件；应验证 `signal_date`、价格时效及执行日期，增加信号唯一键，避免重放。
- **存储路径绑定源码位置：** CLI 的 `storage.py`、`report.py` 用 `__file__` 计算数据和结果目录，安装成 wheel 或搬目录可能改变落盘位置。
- **安全边界不同：** GPT 工具调度禁止 R4；CLI 风控服务另有可显式解锁的 live 配置。前者的硬锁不能证明后者也无法交易。整合入口不得自动导入启动或绕过该独立服务。

以上为 S0 时的发现；S1 已修复资金约束和提前前填报价问题，其余问题仍待后续条目处理。测试通过不代表研究证据或实盘安全已经验收。

## 4. 目标结构与迁移方式

```text
统一 quant 命令（拟新增）
          │
          ├── 数据/研究/扫描/回测服务 ── quant 包（现有 CLI）
          ├── 证据/模拟账户适配器 ──── gpt_quant 包（现有 GPT）
          └── 研究摘要 ───────────── Agent（可选，不参与执行决策）

数据快照 → 因子 → 信号历史 → 后续表现 → 研究证据 → 验证闸门
                                                    │
                                              本地模拟账户
券商风控服务：隔离部署，本期不连通
```

建议新增位置：

```text
CLI_research/
  src/quant/
    cli.py                    # 统一入口，旧脚本保留兼容
    config.py                 # 显式工作目录、数据目录、模式
    contracts/                # 行情、信号、结果、证据版本
    services/                 # 从脚本提炼可测试的服务函数
    integrations/gpt_quant.py # 单向调用现有验证/模拟功能
    features/                 # 动量、量比、突破
    scanner/                  # 扫描、去重、候选留存
    tracking/                 # 未来多期限表现与统计
    jobs/                     # 可重试、幂等的收盘批处理
```

第一步保留两个 Git 仓库：CLI 通过明确的本地开发依赖引用 GPT，不以拼接 `sys.path` 作为正式安装方案。依赖方向为 `quant → gpt_quant`，GPT 不反向导入 quant；两边通过版本化的数据结构通信。

如最终需要单仓库，在整合回归通过并确认未提交成果已保存后，再把 `gpt_quant` 包纳入主仓库；保留两个 Python 命名空间和旧命令别名。不要同时维护两份会继续修改的相同源码，不删除原仓库或改写 Git 历史。

继续使用现有 Parquet；小规模信号也可先用 Parquet 和 JSON 索引。跨文件查询、并发写入或 UI 的实际需求出现后再评估 DuckDB/服务数据库，本期不先建多数据库、多服务架构。

## 5. 先统一的契约

| 对象 | 最低约定 |
|---|---|
| 市场和标的 | 边界统一 `us/cn`，适配 GPT 的 `US/CN_A`；标的使用市场、交易所和代码组合，基准指数另带资产类型 |
| 日线 | 交易所交易日期、UTC 可用时间、OHLCV、来源、抓取时间、复权方式、量纲、可交易状态和质量标记 |
| 数据版本 | 保留快照标识及哈希、股票池时点与成员来源；不把当前成分清单伪装为历史成分 |
| 研究产物 | `schema_version`、`artifact_type`、`run_id`、策略/参数、代码版本、数据快照、成交/费用口径、验证区间 |
| 扫描信号 | `signal_id`、市场/标的、信号交易日、产生和可用时间、特征值、评分版本、原始数据快照 |
| 跟踪结果 | 信号 ID、期限、可成交价格基准、成熟日期、收益/基准超额、缺失原因；未成熟不填 0、不计入胜率 |

未知量纲/复权不能只靠市场名称宣称已验证。虽已有 `normalize_volume()`，仍需确认存量数据的来源证据；混源、拆股/分红以及复权历史变更要触发质检和重建，不静默拼接。

摘要与完整证据分开：Agent 默认读精简 JSON/Markdown；完整滚动折、信号明细和行情保留在磁盘，不强行塞进原先约定的 2KB `metrics.json`。

## 7. Radar 首版规则与评价

首版只针对配置中的美股自选池。现有数据主要按配置标的更新，不能宣称覆盖全美股。

- `ret_1d/5d/20d`：历史收益；所有输入截至信号时点。
- `volume_ratio_20`：当日成交量 / 前 20 个有效交易日均量，分母不含当日；缺量纲或历史不足则无效。
- `breakout_20/60`：与此前窗口高点比较，窗口不含当日；定义用最高价还是收盘价必须固定并版本化。
- 连续异动次数：依交易日历计数，缺失数据不能默认连续；先用透明规则，评分不是上涨概率。
- 过滤条件：最低价格、有效成交额/流动性、历史长度、复权及停牌异常；市值等字段未可靠接入时，不伪造对应过滤结果。

后续表现同时保存信号收盘到未来收盘的描述性收益，以及下一可交易价格起算、含费用的可执行收益；两类口径不得混用。报告包含样本数、收益分布、中位数、胜率、基准超额、极端亏损及未成熟/缺失比例；重叠信号按标的去重或分组，避免把高度相关样本当作独立证据。

先验证单一规则的表现，再讨论综合评分。扩大至全市场或加入网站榜单时，单独验收提供商授权、限流、可用性、覆盖、退市样本和历史股票池；本次未开展外部数据源调查。

## 9. S0 边界与未验证事项

两个仓库均存在大量已修改/未跟踪文件。它们是当前工作成果，不能因整合清理、覆盖、自动提交或重置。S0 只新增此文档，并在 PLAN/STATUS 追加导航记录；S1 按用户授权提交修复和必要依赖，具体范围见 M7_S1.md。两轮均未改变 GPT 仓库文件。

未验证：当前真实源网络连通、行情是否最新、存量 Parquet 是否已全部规范化、历史成分数据真实性、真实模型连接、券商连接、持续模拟运行及任何收益承诺。既有文档包含 Windows 环境和旧数据源状态描述，不应直接当作本机当前状态。
